### Введение

Данный репозиторий содержит программную реализацию Retrieval-Augmented Generation (RAG) системы, разработанной в рамках выпускной квалификационной работы. Система предназначена для автоматизированного поиска и генерации ответов на естественном языке по корпусу внутренней нормативно-справочной документации финансовой организации, а именно инструкций системы «РЦК» (Расчетный центр клиентов).

RAG-подход позволяет сочетать мощь больших языковых моделей (LLM) с актуальной информацией из внутренних документов, не требуя дорогостоящего дообучения модели на специализированных данных. Разработанное решение может служить основой для построения интеллектуального консультанта службы поддержки или помощника аналитика, работающего с регламентированным контентом.


### Цели и задачи

**Цель работы** — создание прототипа вопросно-ответной RAG-системы, обеспечивающей высокую точность и достоверность ответов на русском языке за счёт применения гибридного поиска, двуязычной модели переранжирования и строгой метрической оценки.

Для достижения цели были решены следующие **задачи**:

* Разработан конвейер загрузки и предобработки PDF-документов с использованием Docling.
* Реализован структурно-ориентированный чанкер, учитывающий иерархию заголовков и разделов.
* Построен гибридный поисковый модуль, объединяющий семантический (FAISS) и лексический (BM25) поиск с Reciprocal Rank Fusion (RRF).
* Интегрирован русскоязычный Cross-Encoder (`DiTy/cross-encoder-russian-msmarco`) для переранжирования выдачи.
* Выполнена тонкая настройка мультиязычной эмбеддинговой модели под предметную область.
* Подключена генеративная модель `Qwen2.5-14B-Instruct` с 4-битной квантизацией.
* Создан программный оценочный стенд, автоматически вычисляющий метрики Faithfulness, Answer Relevancy, Context Precision и Context Recall с помощью LLM-судьи.


### Архитектура системы

Система построена по классической RAG-архитектуре и включает три ключевых этапа:

1. **Индексация (Offline)**. PDF-файлы из SQLite-хранилища загружаются через Docling, извлекается текст, удаляются колонтитулы и оглавления, затем текст разбивается на чанки с учётом логической структуры. Полученные чанки векторизуются с помощью дообученной модели и сохраняются в FAISS-индексе.

2. **Поиск (Online Retrieval)**. По запросу пользователя параллельно выполняются два вида поиска:
   * *Семантический* — поиск по векторному индексу FAISS.
   * *Лексический* — BM25-поиск по токенизированному тексту.

   Результаты объединяются методом Reciprocal Rank Fusion (RRF), а затем переранжируются кросс-энкодером для выбора наиболее релевантных фрагментов.

3. **Генерация**. В промпт модели `Qwen2.5-14B-Instruct` включаются отобранные чанки, системная инструкция и вопрос пользователя. Модель генерирует структурированный ответ со ссылками на источники.

Ниже представлена принципиальная схема конвейера:

```
PDF → Docling → Очистка → Чанкер → FAISS + BM25 → RRF → Cross-Encoder → LLM → Ответ
```

### Установка и запуск

#### 1. Клонирование репозитория

```bash
git clone https://github.com/AlexanderZah/rag-system.git
cd rag-system
```

#### 2. Создание виртуального окружения

```bash
python -m venv venv
source venv/bin/activate   # Linux / macOS
venv\Scripts\activate      # Windows
```

#### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

#### 4. Подготовка данных

Поместите SQLite-базу `rck.db`, содержащую PDF-файлы в таблице `instruction_files`, в директорию `data/`. Укажите путь к базе в `src/config.py` (переменная `DB_PATH`).

#### 5. Запуск основного конвейера (Jupyter Notebook)

```bash
jupyter notebook notebooks/main.ipynb
```

Данный ноутбук последовательно выполняет индексацию документов, поиск по вопросам из Excel-датасета и генерацию ответов, сохраняя результаты в Excel-файл.

#### 6. Оценка качества (Jupyter Notebook)

```bash
jupyter notebook notebooks/evaluate.ipynb
```

Ноутбук загружает результаты предыдущего шага и производит покусочную оценку с помощью LLM-судьи.


### Использование

#### Быстрый старт из Python-скрипта

Минимальный пример использования описан в `main.py`:

```python
from src.config import *
from src.data_loader import RCKDataLoader
from src.retriever import AdvancedHybridRetriever, Reranker
from src.generator import EnhancedGenerator
from langchain_huggingface import HuggingFaceEmbeddings

embeddings = HuggingFaceEmbeddings(
    model_name=TRAIN_MODEL_PATH,   # или "sentence-transformers/paraphrase-multilingual-mpnet-base-v2"
    model_kwargs={'device': 'cuda'}
)
loader = RCKDataLoader(embeddings=embeddings, db_index_name=DB_INDEX_NAME)
db = loader.get_index_db(DB_PATH, force_rebuild=True)
all_docs = list(db.docstore._dict.values())

retriever = AdvancedHybridRetriever(db, all_docs)
generator = EnhancedGenerator()

query = "Как заблокировать платёж перед отправкой в банк?"
docs = retriever.retrieve(query, k=5)
context_str = retriever.get_context_str(docs)
answer = generator.generate(query, context_str)

print(answer)
```

### Оценка качества

Для объективного измерения эффективности системы реализован модуль `RAGEvaluator`, использующий LLM-судью (`Qwen2.5-32B-Instruct`). Оценка производится по четырём метрикам, широко применяемым в исследованиях RAG-систем:

* **Faithfulness (Достоверность)** — доля атомарных утверждений в ответе, подтверждённых контекстом.
* **Answer Relevancy (Релевантность ответа)** — степень соответствия ответа сути вопроса.
* **Context Precision (Точность контекста)** — отношение полезных чанков к общему числу выданных.
* **Context Recall (Полнота контекста)** — доля фактов эталонного ответа, покрытых контекстом.

Судья возвращает структурированный JSON с оценками и обоснованием для каждого вопроса. Усреднённые значения по всему датасету позволяют сравнивать различные конфигурации системы.

### Данные

Исходные данные представляют собой корпус из **нескольких сотен PDF-документов** — инструкций по работе с финансовой системой «РЦК». Файлы хранятся в виде BLOB-объектов в таблице `instruction_files` базы SQLite. Метаданные включают: название файла, дату создания/обновления, размер.

Эталонный датасет для оценки содержит вопросы, сформулированные экспертами предметной области, и соответствующие им эталонные ответы (`ground_truth`). Данные размещены в Excel-файле `dataset.xlsx`.


### Модели

* **Эмбеддер**: `sentence-transformers/paraphrase-multilingual-mpnet-base-v2` (768-мерные векторы, 50+ языков). Дообучен на парах (вопрос, релевантный чанк) с использованием Multiple Negatives Ranking Loss.
* **Генеративная модель**: `Qwen2.5-14B-Instruct` (14.7B параметров, контекстное окно до 32K токенов). Загружена в режиме 4-битной квантизации (nf4) для эффективной инференции на доступном GPU.
* **Ранжирующая модель**: `DiTy/cross-encoder-russian-msmarco` — специализированный русскоязычный кросс-энкодер, дообученный на задаче ранжирования пассажей MS-MARCO.


### Тонкая настройка эмбеддера

Для адаптации эмбеддинговой модели к специфике финансовых инструкций выполнен файнтюнинг на собранном наборе пар "вопрос — релевантный чанк". Параметры обучения:

* Функция потерь: `MultipleNegativesRankingLoss`.
* Размер батча: 16.
* Количество эпох: 3.
* Warmup steps: 100.

Дообученная модель сохраняется в директорию `./finetuned_embedder` и автоматически загружается при запуске основного конвейера.
